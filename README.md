# 3Def Creative website

Static website for 3Def Creative, a product animation studio. It is plain HTML, CSS and a little JavaScript, generated by a small Node build script. There is no framework; the only dependency is `sharp`, which makes the responsive images and icons.

Pages: `/` (homepage), `/work`, `/work/[project]` (one per project folder), `/about`, `/contact`, plus a 404 page.

- Design decisions are in [DESIGN.md](DESIGN.md).
- Everything still to replace or confirm before launch is in [TODO.md](TODO.md).

## Running locally

You need Node.js 20 or newer.

```sh
npm install      # once
npm run dev      # build, then serve at http://localhost:8080
```

After changing content, stop the server (Ctrl+C) and run `npm run dev` again.

| Command | What it does |
| --- | --- |
| `npm run build` | Builds the site into `dist/` and lists any `[TODO` markers left |
| `npm run build:strict` | Same, but fails if any `[TODO` markers remain. Use this before launch. |
| `npm run serve` | Serves the existing `dist/` without rebuilding |

## Where things live

```
content/            all text, links, settings and projects (edit these)
  site.json         studio name, domain, email, social links, city, owner, showreel, form endpoint
  home.json         homepage text
  work.json         Work page text and project page labels
  about.json        About Us text
  contact.json      Contact text, form options, FAQ
  proof.json        client logos and testimonials (hidden while empty)
  projects/         one folder per project
public/             files copied to the site as they are
  brand/            your logo files
  media/            showreel, poster, portrait, client logos
  fonts/            Montserrat and Geist Mono
src/                layout and page templates, styles (src/assets/styles.css), script (src/assets/site.js)
scripts/            build.mjs and the local server
dist/               the built site (generated, not committed)
```

## Editing text

Open the matching file in `content/`, change the text between the quotes, and rebuild. Keep the quotes and commas as they are. Breaking them stops the build, and the error names the file.

Placeholders look like `[TODO: confirm reply-time promise]`. Visitors never see the marker. When you've replaced or confirmed the text next to it, delete the marker.

## Adding a project

1. Copy `content/projects/_template` and rename the copy to the project's address, using lowercase words and hyphens, for example `aurora-headset`. The page will be at `/work/aurora-headset`.
2. Fill in `project.md`. The fields at the top (between the `---` lines) are the title, vertical (`Gaming`, `Beauty`, `Wellness` or `Fashion`), category, year, optional client, `featured`, `order` and summary. Below them, write the Overview, Approach, Deliverables and optional Result sections. Delete a section you don't need.
3. Add images to the folder:
   - `cover.jpg`: used on the Work grid, the homepage and link previews. 16:10, at least 1600 px wide.
   - `01.jpg`, `02.jpg`, `03.jpg` ...: gallery images, shown in that order. Any size or shape.
4. Optional video:
   - `video:` for the project page's main video. Use a file in the folder (`film.mp4`) or a Vimeo/YouTube link.
   - `preview:` for a short muted clip (`preview.mp4`, 3 to 6 s, under 2 MB) that plays when someone hovers over the tile on the Work page.
5. Rebuild. The Work grid, the filter, the homepage (if `featured: true`, up to six) and the project page all update by themselves.

To remove a project, delete its folder. To hide one without deleting it, rename the folder to start with `_`.

The Work filter only shows verticals that have at least one project.

## Replacing the showreel and images

- **Showreel loop:** export a muted 10 to 20 second loop, 1920 px wide, MP4 (H.264) and, if you can, WebM. Aim for 4 to 8 MB. Put the files in `public/media/` and set `showreel.loopMp4` and `showreel.loopWebm` in `content/site.json`, for example `"media/showreel.mp4"`.
- **Poster:** replace `public/media/showreel-poster.jpg` with a frame from the reel. It shows before the video starts, when video can't play, and for visitors who turn off motion.
- **Full reel:** set `showreel.fullReelUrl` to a Vimeo or YouTube link (or an `.mp4`). The "Watch the full reel" button appears only when this is set.
- **Portrait:** replace `public/media/portrait-placeholder.jpg`, or add a new file and set `owner.portrait`.
- **Client logos:** put SVG or PNG files in `public/media/clients/` and list them in `content/proof.json`.

You don't need to resize images. The build makes WebP and JPEG versions in several sizes, and browsers download only the size they need.

## Logo files

Your original files are in `public/brand/`. The build makes smaller versions of them in `dist/brand/generated/` but never redraws them.

| File | Used for |
| --- | --- |
| `3def-logo-cream.webp` | Header on every page, mobile menu and footer (cream on the navy background) |
| `3def-logo-white.webp` | Homepage header while it floats over the showreel |
| `3def-logo-black.webp` | Printed pages |
| `3def-logo-navy-square.webp` | Favicon and home-screen icons (cropped to the hexagon icon), and the default link-preview image (centre band, 1200 x 630) |

The header's logo markup is in `src/layout.mjs` (`logoImg`). The icon crop and share-image crop are in `src/lib/images.mjs` (`buildBrandAssets`). If you replace a logo file, keep the same file name and rebuild. The favicon crop assumes the icon sits where it does in the current navy square file; if the new file is laid out differently, adjust `iconCrop` in that function.

## Connecting the form

The brief form sends to whatever is set in `form.endpoint` in `content/site.json`.

**Formspree** (works on any host):

1. Create a free form at formspree.io, with your business email as the recipient.
2. Copy its endpoint, for example `https://formspree.io/f/abcdwxyz`.
3. Set `"endpoint": "https://formspree.io/f/abcdwxyz"` and rebuild.

**Netlify Forms** (only if you host on Netlify):

1. Set `"endpoint": "netlify"` and rebuild.
2. Deploy. Netlify detects the form named `brief`, and submissions appear under Forms in the Netlify dashboard. Turn on email notifications there.

Until an endpoint is set, "Send brief" opens the visitor's email app with the brief filled in, addressed to the business email.

Spam protection: a hidden honeypot field (`_gotcha`) that people never see. Bots that fill it in are ignored.

## Deploying

The site builds to `dist/` with `npm run build`.

- **Netlify:** connect the repository. `netlify.toml` already sets the build command and publish folder.
- **Vercel:** import the repository. `vercel.json` sets the build, the output folder and clean URLs.
- **Cloudflare Pages:** create a project from the repository. Build command `npm run build`, output directory `dist`, and set the environment variable `NODE_VERSION` to `22`.

Before going live, set the real domain in `content/site.json` (`url`) and run `npm run build:strict` to make sure no placeholders are left.

## Quality notes

- Responsive from 360 px, keyboard accessible, and `prefers-reduced-motion` is respected (the showreel shows its poster instead of playing).
- Each page has its own title, description, canonical URL, Open Graph and Twitter tags. Project pages generate theirs from `project.md`.
- `sitemap.xml`, `robots.txt`, `site.webmanifest` and JSON-LD organization data are generated on every build.
- The proof section, client name, Result section, social links and the full-reel button only appear when their content exists.
